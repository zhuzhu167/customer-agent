# PRD：电网营销业扩 Hybrid Customer Agent

更新日期：2026-06-15
版本策略：新建首版规格

## 1. 背景与目标

- 背景：用户希望复刻客户运营 AI Agent 类产品，首发领域绑定电网营销业扩，系统需支持短信和电话两类客户触达渠道，并具备 `Realtime Voice Agent` 能力。
- 业务目标：用 Agent 承接电网业扩客户的咨询、受理、资料收集、进度跟进、供电方案建议草案和回访，降低人工客服重复沟通压力，提高业扩受理效率。
- 用户目标：客户可以通过电话或短信完成业扩咨询、诉求表达、资料补充、预约确认和进度查询；业务人员可以查看 Agent 汇总结果并审批高风险建议或动作。
- 成功指标：
  - `Expansion Request` 建档成功率。
  - `Required Intake Field` 补齐率。
  - 电话转写和摘要可用率。
  - 低压居民/低压非居民请求的直接答复准确率。
  - `Human Approval` 触发准确率。
  - 客户投诉率和误承诺事件数。

## 2. 用户与场景

- 目标用户：
  - 电网客户：居民、小微商户、企业办电联系人。
  - 业务人员：业扩受理人员、客户经理、审批人员。
  - 运营管理员：配置知识库、风险规则、话术、短信模板和渠道。
- 主要使用场景：
  - 客户电话咨询新装、增容、减容、过户、改类等业扩业务。
  - 系统主动电话或短信进行资料缺失提醒、预约确认、进度通知、满意度回访。
  - Agent 根据客户描述收集 `Intake Profile`，创建 `Draft Expansion Request`。
  - Agent 对低压居民和低压非居民请求提供非承诺性的 `Direct Recommendation`。
  - 涉及高压、专变、大容量、重要客户、特殊行业、现场条件不确定，或涉及容量、电价、费用、承诺时限等 `Commitment-sensitive Detail` 时进入 `Human Approval`。
- 前置条件：
  - 已配置短信服务商、语音通话服务商、ASR/TTS/LLM 服务、知识库和业务规则。
  - 客户触达应具备合法授权、退订或拒接处理策略。
  - 初版只作为业扩辅助受理系统，不替代正式电网核心业务系统。
- 触发入口：
  - `Inbound Call`：客户主动拨入。
  - `Outbound Call`：系统基于服务跟进或营销触达任务拨出。
  - `SMS Channel`：客户回复短信或系统发送补充资料链接、确认信息。

## 3. 范围

### 3.1 本期包含

- `Hybrid Customer Agent`，支持 `SMS Channel + Voice Call Channel`。
- `Realtime Voice Agent`，可在电话中低延迟对话、识别客户意图、支持打断处理。
- `Full Business Expansion Intake`，覆盖咨询、诉求收集、分流、资料补齐、过程跟进。
- `Expansion Request` 生命周期：
  - 创建草稿。
  - 动态补齐 `Required Intake Field`。
  - 客户确认后提交。
  - 进入推荐、人工复核、人工审批或后续跟进。
- `Intake Profile` 动态采集：
  - 最小集：客户姓名、联系电话、用电地址、业务类型、客户描述。
  - 扩展集：用电主体类型、预计用电容量/负荷、用电性质、期望办理时间、是否已有户号。
  - 附件或证明材料通过短信链接异步补充。
- `Supply Plan Recommendation` 风险分级：
  - `Direct Recommendation`。
  - `Human Review`。
  - `Human Approval`。
- `Direct Recommendation` 仅覆盖低压居民与低压非居民请求，且不得包含 `Commitment-sensitive Detail`。
- `Human Approval` 覆盖所有非 `Low-risk Action`，以及高风险 `Supply Plan Recommendation`。
- 业务人员工作台：
  - 查看通话记录、短信记录、转写、摘要、请求详情。
  - 审核或修改待审批建议。
  - 批准或拒绝 `Approval-gated Action`。
- 管理配置：
  - 知识库。
  - 风险规则。
  - 话术模板。
  - 短信模板。
  - 渠道配置。

### 3.2 本期不包含

- `Web Chat Channel`。
- 替代正式营销业务系统完成最终业务审批。
- 自动承诺具体容量、电价类别、费用金额或保证办结时限。
- 金融催收、医疗建议、合同签署、在线支付。
- 大规模无授权营销外呼。
- 自研 ASR/TTS 基础模型。
- 多供电公司、多租户复杂结算。

## 5. 业务规则

- `Marketing Outreach` 与电网“营销”不是同一含义。电网营销业扩在本产品内称为 `Power Grid Customer Operations` 和 `Power Grid Business Expansion`。
- 所有 `Outbound Call` 和营销型短信必须满足授权、频控、退订或拒接处理要求。
- `Realtime Voice Agent` 可以执行 `Low-risk Action`，例如预约确认、改约、资料补充、创建草稿请求、发送短信链接。
- 所有非 `Low-risk Action` 均为 `Approval-gated Action`，必须经 `Human Approval` 后执行。
- `Supply Plan Recommendation` 是非最终建议，不等同于正式供电方案或审批结果。
- `Direct Recommendation` 仅允许覆盖：
  - `Low-voltage Residential Request`。
  - `Low-voltage Non-residential Request`。
  - 材料清单、办理路径、预约勘查、流程说明等非承诺内容。
- 涉及以下任一条件必须进入 `Human Approval`：
  - 具体容量。
  - 电价类别。
  - 费用金额。
  - 保证办结时限。
  - 高压、专变、大容量。
  - 重要客户、特殊行业。
  - 现场条件不确定。
- `Expansion Request` 正式提交前，应由客户通过短信或电话确认关键信息。
- 客户拒绝继续沟通、要求人工、表达投诉或风险意图时，Agent 应停止自动建议并进入人工处理队列。

## 6. 主流程与异常流程

### 主流程：Inbound Call 受理

1. 客户拨入电话。
2. `Realtime Voice Agent` 问候并说明身份、录音/转写提示和服务范围。
3. Agent 识别客户业扩意图。
4. Agent 收集最小 `Intake Profile`。
5. Agent 根据业务类型动态追问 `Required Intake Field`。
6. 信息不完整时创建 `Draft Expansion Request` 并短信发送补充链接。
7. 信息完整时进行风险分级。
8. 低风险场景直接输出 `Direct Recommendation`。
9. 高风险场景生成草案并进入 `Human Review` 或 `Human Approval`。
10. 客户确认关键字段后提交 `Expansion Request`。

### 主流程：Outbound Call / SMS 跟进

1. 系统根据任务触发客户跟进。
2. 检查客户授权、频控和黑名单。
3. 通过电话或短信联系客户。
4. Agent 说明来意并围绕资料缺失、预约确认、进度通知或回访沟通。
5. 沟通结果写回 `Expansion Request`。
6. 需要客户补资料时发送短信链接。

### 异常流程

- 客户不接电话：记录未接通，按频控规则安排重试或改发短信。
- 客户要求人工：创建人工处理任务，并附带会话摘要。
- ASR 低置信度：Agent 复述确认，仍无法确认时标记人工跟进。
- LLM 无法判断风险：默认进入 `Human Approval`。
- 短信发送失败：记录失败原因，触发重试或人工提醒。
- 客户退订或拒绝触达：停止 `Marketing Outreach`，保留必要的服务型通知边界。

### 空数据处理

- 无历史客户信息时，Agent 按新客户路径采集最小信息。
- 无匹配知识库答案时，Agent 不编造答案，转为人工或给出“需进一步核实”的非承诺回复。

### 权限不足处理

- 无审批权限的用户只能查看请求和建议草案，不能批准。
- 无管理权限的用户不能修改知识库、规则和模板。

## 7. 验收标准

- 能通过模拟电话创建 `Expansion Request`。
- 能通过短信补齐 `Required Intake Field`。
- 能区分低压居民、低压非居民和复杂请求的风险层级。
- 涉及 `Commitment-sensitive Detail` 的建议不会直接发给客户。
- 通话转写、摘要、字段抽取和审批记录可追溯。
- 未授权或退订客户不会收到营销型触达。
- 客户要求人工时，系统能生成带上下文的人工任务。
